# 第一章時長與可玩性驗收

目標：初次閱讀、完成主要調查與代表性支線約 90–120 分鐘。當前版本仍未達標；沒有真人試玩結果。不要用總分支字數、等待動畫、重複操作或自動測試時間代替遊玩時長。

## 記錄方式

遊戲顯示每份正式存檔的本機前景遊玩分鐘數，讀對話與案件簿均計入，主畫面、背景分頁與章末結算停止計時。舊存檔從零開始，無法還原舊時間；以新遊戲測試。計時約一秒精度，不上傳資料。離開分頁或頁面時保存，正常操作及定期自動存檔也保存時間。

至少三位不同閱讀習慣的玩家，先各自自然遊玩，不規定最低停留時間。記錄：路線、是否完成現場走訪與深入訪談、前景總分鐘、另行人工記錄的休息、覺得困惑或重複的場景、第一次理解證據限制的時刻。不要把同一玩家多次重玩當成三位玩家。

## 驗收路線

1. 透明調查：尊重授權、核對時間與合約、完整回答聽證。
2. 黨團優先：接受管制原案、選擇性公開，確認資源與信任後果可讀。
3. 調查未完：保留公開授權或承認未知，確認不必作無根據指控才能過關。

每條路線都需有清楚目標、足夠人物互動及具體後果。選擇前應知道會承諾什麼，選擇後應看到誰回應，而不只是數值變動。

## 未完成事項

第一章篇幅仍不足，主要角色表情與部分場景仍待完成。幕僚協作、交叉判讀、章內回訪與記者美術已加入；現在可按下列路線開始真人試玩，但不能宣稱已達兩小時。真人數據齊備後，以中位數及範圍描述結果，不以單一慢讀者支持時長宣稱。

## 本版試玩步驟

1. 執行 `npm start`，在瀏覽器開啟 `http://localhost:3000`，選擇「開始第一章」。每位玩家用各自的瀏覽器設定檔，從新存檔開始。
2. 玩家先自然遊玩，主持人不預告正確答案。完成後再用[代表路線報告](chapter-01-route-report.md)的選擇順序做功能複查；複查時間不混入初玩時間。
3. 記錄接案、港口、調查、協商、聽證、章末回訪六階段結束時的人工計時。遊戲主畫面顯示累計整分鐘，「試玩紀錄」顯示六階段近似分鐘；主持人另記錄人工段落時間與離席休息；停留讀案件簿算遊玩，離席休息另外記錄。
4. 最終選擇後記下本機前景分鐘、人工有效遊玩分鐘、章末結果及待辦承諾。只寫實測值，不填估算值。
5. 請玩家用自己的話說明：「核實與公開授權差在哪裡？」「時間線能否證明動機？」「哪些承諾還沒有完成？」記錄原話與卡關位置。
6. 另測一次翻頁後重新開啟、手動存讀檔、未授權出示禁用，以及舊章末存檔的新增回訪入口。這是功能驗證，不算自然初玩。

可複製[空白試玩紀錄 CSV](chapter-01-playtest-records.csv)，每位玩家填一列；空白就是尚未測量。不要記錄真實姓名或其他不必要個資。本機計時不會自動寫入 CSV，必須人工填寫。

## 代表路線與支線覆蓋

| 路線 | 三次訪談 | 重點 | 未覆蓋內容 |
| --- | --- | --- | --- |
| 透明調查 | 技師、家屬、記者 | 三條現場走訪、兩題作證、兩題深入採訪、完整出示 | 幕僚工作板、合約與時鐘互動判讀 |
| 黨團優先 | 技師、記者、幕僚 | 管制原案、選擇性說法、有利短片、過量排程 | 自然初玩後另測工作分工與成果審閱 |
| 調查未完 | 家屬、記者、幕僚 | 不訪技師也有通訊簡報；未授權仍能過關 | 維護文件與技師作證支線 |

三條路線每次都只有三個調查時段，無法把四位人物的內容算進同一次遊玩。三條也不代表所有支線組合或第四種「失控的聽證」結果；後者另由既有路線測試覆蓋。

## 節奏檢查清單

- 調查段：三次往返行程頁是否重複？玩家能否清楚區分現場口述、文件、核實與授權？
- 聽證段：玩家是否有足夠資訊作答？不要以增加空白翻頁或強制等待延長時間。
- 章末回訪：海寧、知言與予澄是否各自帶來新的衝突？玩家是否覺得重述太多、結束太晚？
- 承諾銜接：更正與聽證補充稿即使同日到期，也應分開追蹤；排程、草稿、轉介不等於履行。

## 自動檢查與限制

執行 `npm run playtest` 驗證三條代表路線；`npm run playtest:report` 重建路線報告。自動檢查逐場翻頁、每次主線決策後存檔可讀、未授權出示不改寫狀態及章末承諾仍待履行。報告中的頁數包含決策及行程頁，字元是該路線對話紀錄，不是完整畫面閱讀量。

目前真人有效樣本數為 0；中位數、範圍與 90–120 分鐘達標比例均無法計算。取得至少三位玩家的結果後，先修正卡關與重複場景，再決定需要補充哪些實質互動。

## 遊戲內階段紀錄

案件工具列的「試玩紀錄」可查看階段時間與下載 JSON。新遊戲由零開始；舊存檔已計入的時間顯示為未分類，無法事後判斷發生在哪一階段。開啟案件工具仍計入當前場景階段；切到主畫面、背景分頁或完成章末則停止。離席而分頁仍顯示會繼續計時，需人工扣除休息。

下載僅在點擊後產生本機檔案，包含選擇和待辦，沒有自動上傳。填寫 CSV 時以 JSON 的 `phases` 輔助六階段分鐘、`foregroundMs` 輔助總時間；將毫秒除以 60,000，真人有效時間另外填寫。匯出不是完整存檔，不能用來讀檔。重新讀取較早存檔也會回到那份存檔的時間，不宜用反覆讀檔的總值代表初玩時長。

## 新增聽證追問驗收

三輪聽證可在翻頁或決策時開啟「聽證追問」，各題只能作答一次。維護追問需核實 E04；未訪技師的路線沒有此題。自動代表路線報告尚不包含這三題的支線閱讀量，真人紀錄時請在 notes 註明完成哪些追問。測試透明回答與問題回答，確認章末案件標題仍依原主線證據判定，但幕僚會議與承諾簿保留過量保證、方法或維護問題。

## 夜間補件互動驗收

聽證先選「相信團隊」「驗收視為解決」「七日領款保證」，夜談可開啟夜間補件桌。先試隱去原回答，再改為保留紀錄與限制，確認錯誤稿可重寫、審閱稿不能重複作答、重開後稿件保留。到章末只可查閱。檢查承諾簿仍標待履行，不把稿件當成已發布或補助到位。其他路線沒有這些問題時，不應突然出現三稿。

代表路線自動報告不包含這九段補件說明；真人試玩完成哪些稿件請記入 notes，不能以全部支線稿量當成單次閱讀量。

## 外部審閱驗收

夜談先備妥問題稿，再於工會回訪開啟補件桌，選擇納入意見；於記者回訪保留原稿與異議。確認同稿同人不能重複作答、另一人仍能獨立審閱，重開後兩份意見仍在。檢查未授權原件仍不可出示，報導交易或有利短片造成的專訪暫停不因審閱而解除。

另測沒有備妥稿件、以及夜間會議才備妥的路線，不能替玩家補造已發生的工會／記者審閱。代表路線報告尚不包含此支線，真人完成項目記入 notes。

## 後續排程驗收

夜間會議先備妥稿件，再開啟「發布與回覆排程」。給主角安排發布前核對，確認其餘主角選項停用；重排後分別安排主角核對與予澄聯絡。確認責任、重開續玩，檢查人員、工作與未安排待辦保留。章末只可查看，不能再次分工；承諾仍待履行，授權不變。

此排程未包含在代表路線的支線閱讀統計中，真人試玩請在 notes 記錄安排項目。只安排一項也可確認，沒有強迫玩家填滿兩項。

## 夜間人物交鋒驗收

確認後續責任後開啟「討論後續回覆」，檢查對話中的負責人與工作名稱符合排程，未安排數量正確。若工會或記者曾保留異議，對話應引用該異議；沒審閱時不能寫成已看過。選通知，檢查新增承諾仍待履行；選暫不說明，檢查原工作與等待風險保留。重開不能再次刷關係，章末可查看原回應。

這段動態討論不包含於代表路線主線頁統計；真人試玩請在 notes 記錄完成情況。

## 章末交接驗收

完成第一章後開啟「閱讀章末交接」，翻到第二頁再重開，確認頁碼續接。核對承諾、分工與異議數量；讀完選一項第二日優先意向，確認存檔與章末摘要保留，不能重複選取。來信應顯示尚未驗證，不能突然出現核實證據或既有承諾完成。

此六頁不列入代表路線主線頁數。一般結算停止計時，交接面板開啟時計入前景時間；真人可另記交接段落分鐘作比對，不要重複加進遊戲總時間。第二日流程尚未製作。

### 計時修正與內容驗收更新

新版在章末交接面板開啟時計入前景時間，其他結算活動仍停止計時；舊版漏計的交接時間不回填。真人測試仍須人工另記休息。完整資源與支線銜接快照見 [內容驗收](chapter-01-content-audit.md)，不代表真人時長或所有組合已驗收。
